# 完成任務的保留候選

這是 K15、D06 與 D08 的一部分。核心與清理由 Rust 處理。
Swift 仍只顯示同一個對話框。
模型記憶仍關閉，完整日常與保留驗收尚未完成。

## 何時開始計時

schema 19 在原 SQLite 中加入任務結束時間與聊天來源關聯。
成功、失敗或已核對停止的取消，會在狀態交易中保存結束時間。
期限為結束時間加 90 天。查詢與晚到回報不延長期限。
活躍任務及仍有未知效果的取消不會開始這個計時。
舊資料沒有原結束時間時，保留資料，不用查詢時間或建立時間猜測。

Core 的 `finish`、人類取消、核對結果與工具回報均已接入。
server 使用 `route_at` 的處理時間保存取消的結束時間。
延遲處理不會把舊要求時間當成已停止時間；重送也不重設原時間。
建立時間、決策與原期限仍使用原事件時鐘。
有固定時鐘的 adapter 使用 `record_receipt_at`、`record_receipt_in_at` 或 `device_observation_in_at`。
舊入口使用程序目前時間，不能使用工具自報時間。
`record_task_terminal_in` 只供可信 adapter，且必須共用實際狀態交易。

## 到期後

原 server 維護程序會處理到期任務，每批最多 64 筆。
一次維護會處理所有已到期批次，再返回或建立備份。
同一計時器也等待最近的期限與每日備份，不會喚醒模型。
清理前，先將沒有正文的限制保存到原資料庫外的限制檔。
限制包含任務識別、修訂、原結束時間、清理時間與隨機清理識別，最多 10,000 筆。
接受新任務前會保留相應空間。歷史識別已達 10,000 時，不再接受新任務；查詢、取消與既有清理仍可執行。
是否已清理由受管紀錄核對，不能使用輸入正文自報的到期標示。
舊程式不能讀取新增的限制欄位。舊資料庫也不能移除目前的限制。

Rust 清除原任務目標、scope、決策正文、成果、run checkpoint、操作 intent、目標摘要、工具結果、server 圖片與已關聯聊天。
原輸入與系統回覆共用來源時，等最後一個引用任務到期後才清理。
活躍任務仍引用的來源會保留。
清理會核對 WAL 截斷，避免成功回覆後仍可從目前 WAL 取回正文。

任務、操作與回報識別仍保留。已知效果狀態、次數與費用金額不重設。
未知費用不會自動退回。晚到的有效使用量仍可核對金額，正文證據不再保存。
一般晚到回報不會解決已清除來源的未知效果。
可信 controller 仍可提交已驗證的核對結論；只保存結果狀態，不把證據正文寫回。
已退役的任務識別不能重新建立、修訂或派工。

原已確認和未確認的快照均會清理。重送沿用原標頭與確認識別，不重建舊內容。
快照建立及實際傳送均須核對到期限制。限制鎖忙碌時保留待送要求，等待原計時器重試。
已取出的舊快照也須改送原清除標頭；同一快照含有效記憶來源時仍要核對。
Rust chat 收到 server 的到期任務標示後，清理該任務登記的 PNG。
同像素、不同任務的有效引用仍保留。檔案遭替換時，保留檔案與待清理紀錄。
相同快照重送仍須重試清理；未完成時不能只回覆成功確認。
local executor 沿用原工作清除與實際程序停止核對。只有 ACK 仍不是停止證據。

## 中斷與還原

限制已保存但 SQL 清理失敗時，相關內容讀取會拒絕。
修復、重開或還原較舊 SQLite 後，先重做清理，再提供資料。
資料庫中的清理序號比外部限制新時，拒絕開啟。
原離線還原流程也會帶入任務結束時間與聊天關聯，套用目前限制後再合併可讀的結果與費用。

測試涵蓋限制保存後、SQL 清理後及提交後的真正程序退出。
另有真正 loopback WebSocket，核對已確認與未確認的普通聊天回覆，不須新的輸入或模型呼叫即可清理。
工具回報測試核對原工作清除標頭、晚到正文及時鐘回退。
圖片測試核對任務隔離、共用像素、替換檔案及重送失敗。

```sh
cargo test --locked -p pulse-core --test task_retention
cargo test --locked -p pulse-core --lib retention
cargo test --locked -p pulse-link --lib retention
```

## 剩餘驗收

這項不等於完整 K15。缺少原時間的舊任務、未登記檔案、長期關閉副本、使用者匯出、排程資料與除錯記錄仍需完成各自的保留流程。
離線副本不宣稱即時完成清除。重新連線後才同步原 server 狀態。
尚未通過整機斷電、完整桌面操作、日常情境或 8 小時運行驗收。
Pulse 的清理不控制供應商、檔案系統快照或使用者另存副本。
