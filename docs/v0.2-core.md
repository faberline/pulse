## 可用部分

`pulse-core` 是同程序 library。它沒有 HTTP/WSS listener、桌面 UI、真實模型 client 或地端工具執行器。呼叫者須是可信程式；不能直接把網路傳入的 actor、時間或 receipt 當作權威。

| 能力 | 入口與不變條件 |
|---|---|
| 持久收件 | `ingest` 使用可信 `Origin`；JCS digest；同 key 重播回原 ID；衝突留存且拒絕 |
| 事件 routing | `route` 處理已保存的 typed commands；同一事件多任務變更全成或全退；source event 不因變更失敗消失 |
| 任務/決策 | create/revise/cancel/query/clarify/resume；revision、有效目標、歷史決策、來源、父子與依賴保存 |
| 有界排程 | `claim_next` 最多兩個 active runs；優先序、依賴、deadline、retry wake；等待裝置/批准時不給推理名額 |
| 版本與 checkpoint | run 保存完整版本組合與 checkpoint；`recover` 使用新 epoch 擋舊 worker；不相容版本 blocked |
| 費用 | `reserve` 原子核對 task/day 額度；回 true 才代表新的預留；false 是原 call 的重送，不能再呼叫模型 |
| 未知費用 | `cost_unknown` 保留全部預留；`settle` 需要 usage 證據，重複結算不能改內容；跨日不釋放舊費用 |
| 模擬 intent | `prepare_operation` 只准 `fixture:` 目標；保存 intent、digest、冪等鍵及 run token；未核對操作不能重派 |
| 工具結果 | `record_receipt` 保存可去重的證據；`receipts` 可恢復歷史結果；工具成功或失敗都不自行判定任務目標 |
| 目標完成 | 可信 coordinator 用 `finish` 明確核對目標；未知效果、過期 token、等待狀態或空證據不能完成 |
| 結果核對 | `reconcile` 接受已查證的未執行、已執行或不明結論；不明保持 blocked；晚到結果不完成已修訂的目標 |
| 通知/健康 | 持久 outbox、精確 ACK、滿載反壓、任務狀態/queue age/未知操作計數；均不需要模型 |

Task 的 wall deadline 為建立後 15 分鐘，重啟不重置。模型請求最多八次，重試 wake 最多三次，工具操作最多十六次。費用每日 US$1、每任務 US$0.25，以 Asia/Taipei 換日。呼叫者注入的時間必須來自可信時鐘；這不是接受客戶端任意時間的協定。

DB schema 1 使用 SQLx migration、WAL、FULL synchronous、單連線 writer 與 BEGIN IMMEDIATE。SQLx 0.9.0 的 bundled SQLite 為 3.51.3；啟動仍核對實際 SQLite 版本。DB 必須為 0600 普通檔案，父目錄不能讓其他使用者寫入，且拒絕 symlink。`recover` 只能在取得服務的獨占啟動責任後呼叫，不是任意 worker 的輪詢動作。

## 替身示例

從 repo 根目錄執行：

```sh
pulse_demo_dir=$(mktemp -d)
cargo run --locked --example durable_demo -- "$pulse_demo_dir/pulse.db"
cargo run --locked --example durable_demo -- "$pulse_demo_dir/pulse.db"
```

示例 A 使用 fixture 分析結果。它保存 intent、重開 DB、看到結果未知、核對 fixture receipt，再由 coordinator 完成目標。B 保持 waiting_device。第二次執行使用同一來源 ID，讀取原結果，不重做工作。示例沒有真實工具或模型，也不是主要產品 UI。

## 測試與證據範圍

| v0.1 測試族 | 本候選的 core 子集 | 未包含的部分 |
|---|---|---|
| T01、T02 | typed 多任務事件、原子修訂、取消/晚到結果、查詢/澄清 | 自然語言意圖辨認與桌面呈現 |
| T03 | 收件/routing 的持久邊界、SQL 故障 rollback、真正子程序中止 | 真實網路收件/ACK |
| T07 | epoch、未知模擬效果、不明核對、取消證據與不重派 | 真實裝置 lease/外部 write adapter |
| T09、T13 | queue/等待零推理名額、deadline、有限 retry、原子預算及日界 | 真實 API 請求、429、token 計量與帳單 |
| T15 | run/checkpoint 版本相容性及未來 schema 拒絕 | 軟體發佈與部署 rollback |
| T17、T19 | 持久 receipts、目標與工具結果分開、outbox/ACK/反壓/健康 | 跨雲地 trace、桌面通知及完整成果核對 |
| T20 | 固定 toolchain/lock、fmt/clippy/tests、Linux/macOS CI 與 coverage | CI 未跑完前不視為通過；未獨立接受前不關 issue |

`tests/process_crash.rs` 在四個切點各執行二十個獨立子程序，共八十次。切點為 ingest commit 前、ingest commit 後、routing commit 後，以及模擬效果保存後但 receipt 保存前。子程序以 exit 結束，不跑 Rust destructors。最後一種情境另用獨立 SQLite sink 計數，證明核對後效果仍只有一次。

`crash_boundary_child` 是忽略的子程序入口，由父測試以 `--ignored` 明確執行八十次；不是漏跑的接受 gate。其餘正常測試仍須全部通過。此矩陣未模擬斷電、磁碟硬體失效或真實 provider。

本機及 CI 使用：

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
mkdir -p coverage
cargo llvm-cov --workspace --locked --ignore-filename-regex '/(tests|examples)/' --lcov --output-path coverage/lcov.info
cargo llvm-cov report --ignore-filename-regex '/(tests|examples)/' --summary-only
```

toolchain 固定 1.96.1，coverage 工具固定 cargo-llvm-cov 0.8.5，並需要相同 toolchain 的 llvm-tools-preview。coverage 分母為 `src/` 的程式行/region/function；排除測試及 fixture example，不排除 domain、policy 或恢復邏輯。不設虛構的 99% 接受門檻。CI 保存 LCOV artifact 七天，summary 留在 job log。

精確 commit、當前 head 的本機結果、coverage 數字與 CI 狀態，記在對應 issues/PR。工作目錄的歷史成功不能代替新候選證據。

## 未實作及接受限制

原生批准/拒絕操作、裝置可達性與續租、HTTP/WSS 認證、原始 wire JSON 的重複 key 檢查、rich UI、排程訂閱、知識檢索、retention/deletion、備份/還原與真實 provider/AW 閉環仍屬後續階段。核心可保存 waiting_approval/waiting_device，但不提供可繞過那些 gate 的假批准或假裝置事件。

版本欄位保存固定 ID 與相容性。完整 prompt/tool manifest registry 隨相應 adapter 實作；不能把 fixture 版本當作已核對的正式模型契約。費率與 receipt 證據也由可信 adapter 提供，library 不自行查供應商帳單或驗證遠端 artifact。

本候選沒有任意 shell、真實寫入或公開 listener。不得因通過本機核心測試而接受完整 T01–T20、完成 v0.1、完成 v0.2 release，或宣稱完整助理可用。
