# 工具結果來源清除候選

這是 D06 的前置工作。模型仍不會收到記憶正文。
Swift 只處理介面。來源核對、保存、清除與恢復由 Rust 處理。
schema 為 16，remote workflow 為 `pulse-remote-16`。
policy 為 `approved-effects-memory-fences-4`。

## 保存與清除

工具結果、聊天與來源關聯在同一交易保存。
工具結果事件仍使用原本的穩定來源識別。
若事件已保存而結果交易失敗，來源清除仍能從 read 紀錄找到該事件。
尚未保存成操作要求的模型提議事件，也會依原 token 的任務修訂清除。
這不會刪除獨立的人類訊息。

來源被移除時，Rust 清除結果正文、事件正文、聊天及已保存的原圖和圖片分塊。
聊天副本沿用沒有正文的清除通知，保留原確認識別。
批准卡片也會追蹤來源。清除後的卡片不再附帶提議或圖片資料。

`memory_erased_reads` 只保存被清除的 read 識別。
已知結果改為內部的 `discarded` 狀態，表示證據已丟棄。
它不是成功回報，也不是可供任務驗收的證據。

## 晚到回報與未知操作

Rust 在接受結果或圖片前取得來源限制鎖。
這個鎖核對該 read 的原任務修訂，包含目前任務已換修訂的情況。
來源已移除時，回報不會再次寫入事件、聊天、結果正文或圖片。
裝置、epoch、任務與修訂仍須符合原 read。
原封不動重送的訊息仍沿用原確認，不改變來源識別。

只讀工作回報完成或拒絕後，可以結束等待；正文仍會丟棄，任務不會恢復。
回報未知時仍保留未知。
若操作在清除前尚未取得有效回報，晚到資料不能把它改成成功或未執行。
原操作帳本與已保留的費用仍保留，不重做效果，也不自動退回預算。

人類建立新的獨立任務修訂後，可以核對新的有效證據。
只有帶清除標記、且屬於較舊修訂的已丟棄 read，才會略過舊證據核對。
目前修訂的缺失或未知回報仍不能通過。

## 失敗與升級

來源限制先保存到資料庫外，再清除 SQL 資料。
SQL 清除失敗時，舊圖片下載與新結果保存都會停止。
修復後先重做清除，再處理原訊息。
schema 15 升級會補上舊工具聊天及批准卡片的來源關聯。
已失效的來源會在開啟資料庫時清除，不能因升級恢復正文。
