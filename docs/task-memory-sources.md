# 任務的記憶來源關聯候選

這是 D06 的必要前置工作。它不開啟模型記憶，也不代表 D06、D08 或 K15 已接受。
Swift 沒有新增任務或記憶規則。這些規則由 Rust Core 處理。
schema 為 17。remote workflow 為 `pulse-remote-18`，policy 為 `approved-effects-memory-fences-5`。
地端工作與雙向傳輸清除見 [地端工作清除](worker-source-erasure.md)。
模型聊天的來源追蹤與清除候選見 [衍生聊天清除](derived-chat-erasure.md)。
版本不符的舊 run 需重新核對，不能自動視為新規則已驗收。

## 來源關聯

可信任的 controller 可用 `Store::bind_task_memories` 提交 Human 要求。
Core 保存原要求、Human 來源事件、任務修訂、記憶修訂、來源 UUID 與到期時間。
關聯與事件在同一交易保存。紀錄不含記憶標籤或正文，不改變任務目標、工具範圍或操作批准。
模型、工具與外部來源不能建立這種關聯。

每個任務修訂只能採用一次明確的來源集合。每次 1–8 筆，最多保存 1,000 筆關聯歷史。
同一要求識別重送會返回原關聯；改動內容會拒絕。重送已失效的要求不會恢復來源。
Core 以目前修訂的 run、operation 與地端讀取紀錄核對尚未開工，不能事後把舊成果歸給新來源。
費用與工具次數仍跨任務修訂累計，不因更換記憶而重設。

這個候選 API 只返回沒有正文的來源關聯。尚未新增對話命令，也不會將關聯當成模型提示或工具權限。

## 修正、忘記、撤銷與到期

記憶來源移除時，Core 在同一來源清除交易使對應關聯失效。
若任務仍在使用該修訂，舊 run 失去執行權限；執行 checkpoint 與任務 evidence 清空，待批准／已批准要求失效。
任務改為需核對來源。若操作結果仍未知，保留未知狀態與原操作帳本，不冒稱取消成功。
已失去記憶來源的傳輸結果不再保存正文。未知操作仍保留未知，不能恢復舊 run 或驗收任務；見 [工具結果來源清除](derived-tool-results.md)。

修正記憶不會讓任務自動改用新版。須先由 Human 修訂任務，再明確採用新的來源。
先前保留或未知的費用仍保留，已發生的費用仍可核對結算。

來源清除不依賴通知容量。佇列滿時先保存一個沒有正文的變更標記；remote 迴圈在有空間時交接目前狀態。
新關聯本身需要正常事件容量。容量不足會回滾整筆採用，不留下半筆事件或來源關聯。

## 執行核對與恢復

Core 的費用保留、advance、finish、提議與操作準備入口會先取得有關聯任務的 restriction lease。
這是一個本機來源限制鎖。它先核對資料庫外的撤銷證據、套用來源清除，再核對目前任務與來源。
若撤銷證據已保存而 SQL 失敗，舊的正面資料不能讓這些本機提交繼續。修復後會先重做清除。
沒有引用記憶的任務不因此取得來源權限，也不必依賴記憶 keeper 可用。

Core claim、SQL 共用入口、remote context／結果與傳輸允許核對也檢查來源修訂與 Human 採用事件。
已排入真正傳輸佇列的讀取，在來源移除後會失去傳送允許。
context／回覆／提議、手動讀取與傳輸允許入口也已取得這個限制鎖；派工迴圈與送出前的完整核對仍待完成。
這些 SQL 核對不能代替資料庫外的限制鎖。`TaskMemoryLease` 只供有界本機提交，不可持鎖等待 provider。

正常重開會從同一 keeper 重做撤銷。測試亦核對：關聯已存在的刪除前快照，搭配目前 keeper 時，不能恢復原 run。
這不是任意還原保證。早於關聯建立的備份、完整世代切換、所有副本及保留期限仍屬正式還原工作。
