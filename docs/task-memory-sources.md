# 任務的記憶來源關聯候選

這是 D06 的必要前置工作。它不開啟模型記憶，也不代表 D06、D08 或 K15 已接受。
Swift 沒有新增任務或記憶規則。這些規則由 Rust Core 處理。
schema 為 17。remote workflow 為 `pulse-remote-22`，policy 為 `approved-effects-memory-fences-9`。
地端工作與雙向傳輸清除見 [地端工作清除](worker-source-erasure.md)。
模型聊天的來源追蹤與清除候選見 [衍生聊天清除](derived-chat-erasure.md)。
版本不符的舊 run 需重新核對，不能自動視為新規則已驗收。

## 來源關聯

可信任的 controller 可用 `Store::bind_task_memories` 提交 Human 要求。
Core 保存原要求、Human 來源事件、任務修訂、記憶修訂、來源 UUID 與到期時間。
關聯與事件在同一交易保存。紀錄不含記憶標籤或正文，不改變任務目標、工具範圍或操作批准。
模型、工具與外部來源不能建立這種關聯。

每個任務修訂只能採用一次明確的來源集合。每次 1–8 筆，最多保存 1,000 筆關聯歷史。
同一要求識別重送會返回原關聯；改動內容會拒絕。重送已失效的要求不會恢復來源。
Core 以目前修訂的 run、operation 與地端讀取紀錄核對尚未開工，不能事後把舊成果歸給新來源。
費用與工具次數仍跨任務修訂累計，不因更換記憶而重設。

這個候選 API 只返回沒有正文的來源關聯。尚未新增對話命令，也不會將關聯當成模型提示或工具權限。

## 明確採用父任務的來源

可信任的 controller 可呼叫 `Store::inherit_task_memories`。
呼叫必須來自 Human，並帶入一般 `TaskMemoryRequest` 與預期的父任務修訂。
Core 從子任務的 `parent` 欄位取得實際父任務，不能任意指定另一個來源任務。
採用時，父任務須仍在指定修訂，請求的來源集合須與該修訂完全相同。
子任務仍須尚未開工。目標、工具範圍、期限、費用與呼叫次數不會改變。

Core 在同一限制鎖與交易中核對父來源，再保存子來源與 Human 採用事件。
事件另記 `task_memory_parent`，包含父任務、父修訂及原採用事件。
這些資料沒有記憶正文或標籤，也不延長原來源期限。
同一要求重送必須保留原父修訂。不能用一般採用入口重送，藉此移除父來源證據。

後續本機提交會逐層核對原 Human 事件、完整內容摘要、父子關係與來源集合。
父採用紀錄遺失、被改動或形成循環時，子任務不能繼續使用該來源。
最多核對 32 層，並保留既有 1,000 筆採用歷史上限。
父任務之後修訂，不會自動替換子任務已明確採用的來源。
原記憶被忘記、修正、撤銷或到期時，所有已採用該來源的後代仍會由原清除交易失效。
已保留的未知費用不會退回。

這是既有事件 payload 的擴充，沒有新增資料庫或 wire 格式。
舊程式不具備父來源鏈核對，不能用這項候選接受跨版本部署。
模型記憶啟用前，仍須完成版本門檻與正式升級驗收。

測試核對多層採用、重送、父修訂改變、到期、修正、忘記、舊快照加目前限制檔、來源破壞、循環、深度與通知容量。
server 測試另核對子任務提示仍沒有記憶正文，以及忘記父來源後會清除子任務回覆。
這些測試使用合成內容與受控回覆，沒有呼叫付費 API。
對話入口、自動拆分任務的完整來源繼承及模型記憶啟用仍未完成。

## 修正、忘記、撤銷與到期

記憶來源移除時，Core 在同一來源清除交易使對應關聯失效。
若任務仍在使用該修訂，舊 run 失去執行權限；執行 checkpoint 與任務 evidence 清空，待批准／已批准要求失效。
任務改為需核對來源。若操作結果仍未知，保留未知狀態與原操作帳本，不冒稱取消成功。
已失去記憶來源的傳輸結果不再保存正文。未知操作仍保留未知，不能恢復舊 run 或驗收任務；見 [工具結果來源清除](derived-tool-results.md)。

修正記憶不會讓任務自動改用新版。須先由 Human 修訂任務，再明確採用新的來源。
先前保留或未知的費用仍保留，已發生的費用仍可核對結算。

來源清除不依賴通知容量。佇列滿時先保存一個沒有正文的變更標記；remote 迴圈在有空間時交接目前狀態。
新關聯本身需要正常事件容量。容量不足會回滾整筆採用，不留下半筆事件或來源關聯。

## 執行核對與恢復

Core 的費用保留、advance、finish、提議與操作準備入口會先取得有關聯任務的 restriction lease。
這是一個本機來源限制鎖。它先核對資料庫外的撤銷證據、套用來源清除，再核對目前任務與來源。
若撤銷證據已保存而 SQL 失敗，舊的正面資料不能讓這些本機提交繼續。修復後會先重做清除。
沒有引用記憶的任務不因此取得來源權限，也不必依賴記憶 keeper 可用。

Core claim、SQL 共用入口、remote context／結果與傳輸允許核對也檢查來源修訂與 Human 採用事件。
已排入真正傳輸佇列的讀取，在來源移除後會失去傳送允許。
context／回覆／提議、手動讀取與傳輸允許入口也已取得這個限制鎖。provider 的送出與等待核對見下節。模型讀取及已批准的 browser／computer 派工也已加入限制鎖；操作卡片發布與聊天快照也已加入原修訂的來源核對；見 [衍生聊天清除](derived-chat-erasure.md#卡片與快照建立)。其他 adapter 的完整核對仍待完成。
這些 SQL 核對不能代替資料庫外的限制鎖。`TaskMemoryLease` 只供有界本機提交，不可持鎖等待 provider。

正常重開會從同一 keeper 重做撤銷。測試亦核對：關聯已存在的刪除前快照，搭配目前 keeper 時，不能恢復原 run。
這不是任意還原保證。早於關聯建立的備份、完整世代切換、所有副本及保留期限仍屬正式還原工作。

## provider 送出與等待核對

remote 在預留費用後，先呼叫 `Store::validate_model_call`。
Core 核對完整 run token、任務修訂、Planning 階段、讀取範圍與目前模型回合。
同一呼叫須仍有屬於該任務的有效費用保留，且保留金額沒有退回。
有來源關聯時，先取得短期限制鎖，套用目前撤銷與到期，再核對 Human 事件及完整父來源鏈。
驗證失敗時，不會開始輪詢 HTTP future，也不會自動另發一次請求。

等待期間，remote 每秒重新核對一次；已知的任務或來源期限更早時，會在期限重查。
資料庫或限制檔無法核對時也停止等待。
這是檢查間隔，不是作業系統、資料庫或磁碟受阻時的延遲保證。
來源限制鎖只涵蓋本機核對，不會持鎖等網路。
其他程序寫入的限制也會在下一次核對被讀取。

失效時會丟棄本機 HTTP future。已送出的內容無法因此收回。
這不證明 provider 停止執行、刪除資料或不再收費。
結果不明時仍保留原費用；不自動重試。
完整回覆若先抵達，仍先保存已知使用量，再由既有結果入口核對是否可套用。
這些核對不能構成跨 provider 的原子撤銷，也不授權把記憶正文加入提示。

本機測試使用惰性 future 與受控 HTTP 等待。
測試核對送出前零輪詢、等待中取消／修訂／恢復／父來源撤銷、舊回覆拒絕及原費用保留。
實際 provider 停止、費用與兩家完整記憶流程尚未驗收。

## 工具派工核對

`dispatch_model_read` 與 `dispatch_approved_action` 先讀取候選，再取得該任務的來源限制鎖。
取得鎖時，Core 會核對資料庫外的撤銷紀錄，並先完成必要清除。
不會在持有 SQL 寫入交易時等待來源鎖，避免單一資料庫連線互相等待。

取得來源鎖後，server 重新開啟交易並讀取目前任務或操作要求。
任務修訂、run、批准內容、來源、期限及 worker 連線都須仍有效。
等待來源鎖或 SQL 期間經過的實際時間，也會納入期限核對。
任務次數、批准消耗、操作帳本、派工紀錄及傳輸佇列仍在同一交易提交。
佇列寫入失敗時，整筆派工回滾；有效批准仍可在原限制內重試本機提交。
這不會重試已送出的未知操作，也不退回原費用。

若撤銷已寫入限制檔，但 SQL 清除尚未成功，這兩個入口拒絕派工。
修復資料庫後，先重做清除，不能從舊的正面 SQL 繼續工作。
來源證據失效或來源鎖暫時忙碌的候選會被跳過，讓其他有效且不相關的工作繼續。
鎖忙碌不會消耗批准或清掉提議。鎖釋放後，仍有效的原工作可再核對。
來源鎖在本機提交後釋放。真正送往地端前，仍須通過原有的傳輸允許核對。

新增回歸使用合成來源、SQL 故障與受控 helper。
測試核對只有限制檔撤銷時零派工、修復後不復活、其他任務不被擋住，以及批准與佇列回滾後只執行一次。
這不是原生視窗實機驗收，也不開啟模型記憶。

## 仍須完成

模型提示仍然沒有記憶正文。測試明確核對這個邊界。
開啟前仍須完成：所有 adapter 的限制鎖與送出前核對、在途工作停止、自動拆分任務的完整來源繼承、完整衍生聊天／提議／附件清除、地端及關閉副本清理與正式還原。
也需要兩家 provider 的完整流程與實機驗收。

checkpoint、task evidence、模型／工具聊天、提議事件與 server 圖片已有清除候選。
操作 intent、原派工內容與地端 journal 也已加入清除候選。
原操作帳本保留。目前 process 持有的原生 PNG 已加入依任務／修訂清除候選；見 [程序生命週期](owned-process-lifecycle.md)。舊 PNG、硬退出資源、瀏覽器 profile 與關閉副本仍未完整清除。
不能把這個候選當作已可安全將記憶加入模型提示的證據。
