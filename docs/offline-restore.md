# Rust server 離線還原候選

這個入口會替換原資料庫。它與只產生隔離副本的 `check-offline-backup` 不同。
目前只有擁有者建立的隔離測試資料通過驗證。尚未操作日常資料，也未接受完整 K15、D06 或 D08。

## 使用方式

先停止所有使用原資料庫的 Pulse 程序與 Core 連線。
保留原位置的金鑰、目前刪除限制與加密備份。
`PRIVATE_DB` 是原資料庫位置。`BACKUP` 是尚未過期的 `.pulsebak` 檔案。

```text
pulse-server restore-backup PRIVATE_DB BACKUP
```

命令同時取得 server 鎖與 Core 的獨占使用鎖。
仍有連線時會拒絕，不會強制停止其他程序。
檔案須為目前擁有者的私有檔案。符號連結與多重硬連結會拒絕。
只有空白、遺失或損壞的原始資料庫也可使用此入口。
金鑰與目前刪除限制不能缺少，也不能從舊備份取代。

程序中止時，保持全部資料庫使用者停止，再執行：

```text
pulse-server resume-restore PRIVATE_DB
```

不要手動搬動候選、清除日誌、修改 SQLite 版本或移除使用鎖。
正常指令會拒絕未完成的切換。
已完成的 `resume-restore` 只核對原世代，不會回退後來的任務、記憶、配對或費用。
尚未開始切換的準備工作則會重新讀取目前資料，再建立候選。

## 還原後的行為

所有舊裝置與配對碼失效。已知舊裝置 ID 及 token 雜湊持續退役。
必須建立新配對碼，並用空白本機設定檔重新配對。
server 會核對還原世代。舊式或其他世代的要求不會消耗新配對碼。
對話框與 local executor 各自配對。還原命令不會啟動任何工作。

舊任務保留供核對。它們不會自動排隊，也不能用修訂或繼續命令重新啟動。
需要繼續的工作須重新確認，再建立不同 ID 的新任務。
已知結果與原 receipt 保留。未知操作仍是未知。
舊排程取消，舊批准失效，未處理的舊事件不會產生新工作。

能讀取且完整通過核對的目前資料會合併進候選。
這包括較新修訂、原 receipt、已結算費用、未知預留費用及撤銷證據。
互相矛盾的原始結果或費用會使切換失敗。
目前資料損壞時，程式仍盡可能保存可讀的退役識別與費用日期限制。
輸出會明示是否合併了可讀的目前記錄，不能把 `false` 當成帳務完整。

未知費用保留原預留金額。已核對的原始結算才能取代它。
新模型支出封鎖至還原／續接當日結束，使用 Asia/Taipei 日期。
已知費用日期若更晚，封鎖延長至該日。
之後的新任務仍受原本的每日、每任務及呼叫次數限制。

## 切換與保存

候選首次寫入時即使用隔離版本。
程式先核對完整加密備份、migration 清單、資料庫完整性、外鍵及身分。
接著合併目前可讀記錄，重放最新刪除限制，清除到期記憶並封鎖舊工作。
等待續接期間若跨過記憶期限，會先保存新的刪除限制，再建立更新過的候選。

原始 main、WAL、SHM 與 journal 會各自加密保存。
這些檔案保存原始核對證據，不會附加到新資料庫。
加密使用獨立的 HKDF 用途，不能冒充一般備份。
單個原始檔案上限 512 MiB，合計上限 1 GiB。

進度保存在 `<database>.restores/<generation>/`，目錄權限為 `0700`。
進度含 HMAC，這是用原金鑰驗證內容未被改動的證明。
在修改原檔之前，程式先保存外部未完成切換限制。
它會核對所有原檔及日誌，再逐一移除原檔，原子搬入候選並同步磁碟。
啟用前再次核對完整影像與日誌缺席，最後才公布已完成的世代。
未完成或被改動的進度、候選、原檔與加密證據會拒絕續接。

成功後會清除本次的已知明文準備目錄。
一般 server 維護會清除到期的受管加密副本；期限仍為建立後 30 天。
目前世代只留下不含正文的進度，以便核對重複續接。
切換中止時會保留需要的證據，直到續接完成才做後續維護。
停機期間沒有清理程序；檔案系統歷史快照與 SSD 歷史區塊也未受此保證涵蓋。
因此不能把此入口當成完整 K15 的實體保留驗收。

## 證據範圍

- `tests/restore.rs` 核對可讀、遺失及損壞原檔、刪除限制、目前結果／費用、日期支出封鎖、退役任務及重複續接。
- Core 子程序測試核對切換八個中斷點、部分啟用寫入、WAL 尚未合併的資料、到期刷新中再次中止，以及被改動的檔案拒絕。
- 加密測試核對空白／小型原始檔案、完整往返、錯誤金鑰、截斷、內容改動及用途互換拒絕。
- `crates/pulse-link/tests/server_lifecycle.rs` 執行真正 CLI 與 server，核對舊憑證拒絕、世代配對、兩角色 WebSocket 與零模型／工具工作。

測試不呼叫付費 API，也不讀取原生 Keychain。
完整日常資料還原、原生介面、遠端部署、長時間運行與目前 head 的 CI 須分別提供證據。
