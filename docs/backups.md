# 本機備份與還原檢查候選

server 現在會在啟動時清理到期記憶並核對備份。
當天沒有完整的備份時，先建立備份，再開放連線。
server 運行期間，在下一個記憶期限、UTC 日期切換或備份期限到達時喚醒。
新記憶改動也會喚醒維護程序，重新計算下一個期限。
等待時沒有模型呼叫，也不以固定頻率呼叫模型。

## 保存方式

- `<database>.backups/` 是專用的 `0700` 目錄。完整檔案名稱是 `<建立時間>-<隨機 UUID>.pulsebak`，權限為 `0600`。
- `<database>.backup-key` 保存獨立的隨機金鑰，權限為 `0600`。金鑰不放進備份；資料庫只記它的指紋。遺失或不符時拒絕繼續，不會自動換一把金鑰。
- `<database>.memory-restrictions.json` 仍是目前刪除限制。它不跟舊備份一起回退。
- 以上資料、金鑰與暫存檔都由 `.gitignore` 排除。程式拒絕非擁有者、開放權限、符號連結及硬連結的檔案。

保管備份時也須保管金鑰和**目前**的刪除限制。只有備份檔不能還原。
這一版沒有異地保存或金鑰遺失救援。

備份採用 [SQLite 序列化 API](https://www.sqlite.org/c3ref/serialize.html) 和持有寫入鎖的交易產生一致影像。
影像留在記憶體，不寫入未加密的暫存檔。
目前單份資料庫上限為 512 MiB；超過時回報失敗。
這是目前的容量限制，不能宣稱更大資料庫已通過驗證。

加密使用 [ring 的 HKDF](https://docs.rs/ring/latest/ring/hkdf/index.html) 與 AES-256-GCM。
每份備份的隨機識別產生獨立的檔案金鑰。
每個 1 MiB 區塊使用遞增 nonce；nonce 是每次加密必須不同的值。
完整標頭也參與驗證。最後有經驗證的結束記錄與總長度檢查。
改動、截斷、交換區塊或附加內容均被拒絕。

檔案先寫成加密 `.partial` 並同步磁碟，再以不覆寫既有檔案的原子重新命名公布。
最後才保存每日備份檢查點。
同日重啟會核對完整檔案雜湊，檔案遺失或內容不符時重新建立。
未完成的加密暫存檔會在下次啟動清理。
同一天若在公布後、檢查點保存前斷電，可能留下兩份完整備份，沒有覆寫或未加密檔案。

備份有效期為建立後 30 天。還原檢查拒絕過期備份。
維護先驗證檔案標頭、檔名及擁有者，再刪除到期的受管檔案。
不認識的檔案會保留並使本次維護失敗。
server 停機期間無法清理磁碟，重新啟動時先補做；因此尚未證明停機期間也能達到 K15 的實體保留上限。
檔案系統歷史快照與 SSD 的歷史區塊不在這個清理保證內。

## 檢查備份

`pulse-server check-backup PRIVATE_DB BACKUP NEW_DIRECTORY` 只做還原檢查。
`NEW_DIRECTORY` 不得存在，其父目錄須為擁有者的私有目錄。
現有目錄與檔案不會被覆寫。

程式用目前資料庫的金鑰與刪除限制驗證完整備份，再寫入獨立的私有候選目錄。
首次寫入前就把 SQLite 的 `user_version` 改成隔離值 `2147483647`。
目前的 `Store::open` 會拒絕這個值，無法用候選資料直接啟動 server。
檢查失敗或程序中止時，已寫入的候選仍保持隔離。
程式只核對 migration 的完整清單與校驗值，不對候選執行升級。

檢查還包括 SQLite integrity、foreign keys、owner、目前刪除限制與 90 天記憶期限。
Core 恢復會撤銷舊批准、更新執行 token，並將未核對操作保留為未知。
檢查過程不啟動模型、地端工具或任務。
它會回報候選中的記憶、任務與未知任務數量。

這尚不是正式還原與切換功能。仍需在停機切換時重新套用最新限制，撤銷裝置憑證與地端派工，核對原 receipt，再做原子切換及失敗恢復。
不要手動改隔離值來啟動候選。
完整 K15、D06 和 D08 仍未接受。

## 停機切換前的連線保護

Rust Core 現在為每個 `Store::open` 持有資料庫使用鎖。
一般連線可以共用，所以 server 運行時仍可用 CLI 配對或撤銷裝置。
匯出的連線池與分離連線也會保留使用鎖。
只有關閉並釋放全部連線和連線池後，`DatabaseMaintenance::try_acquire` 才可取得獨占鎖。
獨占鎖存續期間，新的 `Store::open` 會在建立或修改資料庫前失敗。
程序突然結束後，作業系統會釋放它的鎖。

`<database>.use-lock` 是穩定的空白檔案，權限為 `0600`。
不要刪除或替換這個檔案來解除鎖。
程式會核對擁有者、權限與檔案連結。
相同父目錄的路徑別名會使用同一把鎖。
此機制只協調使用 Core 的連線，無法阻止其他程式直接開啟 SQLite。
較舊的 Pulse 也不認識這把鎖；正式切換前仍須關閉它。

這項 API 只提供獨占存取資格。
它不會還原資料、撤銷裝置、核對執行結果或切換檔案。
正式還原功能與上述接受條件仍未完成。

## 已有證據

- `tests/backup.rs`：每日一次、重新啟動、來源刪除、90 天到期、30 天備份期限、金鑰錯誤、損壞、私有權限、未知操作、舊批准撤銷與 migration 失敗隔離。
- `tests/database_access.rs`：共用連線、匯出連線池、分離連線、父目錄別名、不安全檔案拒絕，以及真正的子程序中止後鎖釋放。
- 加密模組測試：完整資料往返、錯誤金鑰、標頭與內容改動、截斷、區塊交換及附加內容。
- `crates/pulse-link/tests/maintenance.rs`：真正的到期計時、新期限喚醒、零模型工作，以及 server 子程序突然中止／重啟／HTTP 健康檢查／隔離檢查指令。

完整桌面流程與目前 head 的 hosted CI 仍須另外驗證。
