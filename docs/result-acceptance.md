# 人類確認成果

在單一對話框輸入「接受成果 A」或「確認 A 的成果」。
沒有指定任務時，只能有一項待確認成果。
對象不明確或成果未顯示時，Rust 保留草稿，不建立新工作。
這個流程由 Rust 處理。Swift 只呈現介面。

Rust 先保存目前顯示的任務、修訂、訊息識別和正文 SHA-256 摘要。
離線及重啟後，待送要求沿用原證據。
Server 不從較新的快取猜測使用者看過哪個版本。
舊客戶端只送文字時，server 會要求重新查看成果。

Core 核對已保存的模型回覆、目前聊天正文和原修訂。
取消、修改、來源到期、未核對的操作或舊證據都不能完成任務。
只有已認證的 chat 人類來源可以確認。
確認不批准工具、不重做操作，也不釋放未確認費用。

成功後，任務變為 `succeeded / human_accepted_result`。
完成時間與狀態在同一交易保存，供 90 天保留期限使用。
重送不重複完成通知，也不重設完成時間。
執行期限已過仍可確認已保存成果，因為這一步不開工。
原文字成果匯出內容保持相同。

目前只支援沒有記憶來源歷史的讀取任務。
舊成果缺少確認證據時，會拒絕確認。
模型記憶仍關閉。完整 D02、D06 和 K15 仍待驗收。
這項功能不證明模型回答正確，只記錄人類接受了哪份成果。

資料庫 schema 保持 19。remote workflow 改為 `pulse-remote-23`。
prompt、tools、policy、模型、金鑰與費用上限保持原值。
舊 workflow 仍受既有版本核對限制。

測試使用自有合成資料，不呼叫付費 API。
`tests/result_acceptance.rs` 核對 Core 交易、重送、權限、取消、保留與故障回滾。
`crates/pulse-link/tests/result_acceptance.rs` 核對真正模型回覆保存入口、角色、舊成果和匯出。
Rust 對話迴圈測試使用真正 WebSocket 和記憶體憑證替身。
`server_lifecycle` 另啟動真正 server 程序，核對重啟後不重做工作。
這些測試不代替 macOS Keychain、SwiftUI 畫面或完整日常實測。
