# v0.4 只讀結果核對候選

工作對應 #18，沿用 draft PR #15。使用者可在原本的對話框輸入：

```text
核對 A
繼續 A
```

這是兩則訊息。核對先檢查證據，不呼叫模型或 local。結果仍未知時保持停止。已知憑證通過後顯示「證據已核對，可繼續」。之後的「繼續」才領取原 run 的下一 round，使用已保存的工具證據。任務不會自行變成成功。

## 核對條件

只有 Human event 可要求核對。server 檢查 task/revision、只讀 scope、取消、期限、未決工作與費用。憑證沿用傳輸時綁定的 device、operation、revision；內容與 digest 使用 core 和 transport 共用的 `ReadOutcome` 驗證，不另外定義寬鬆格式。

真正 Unknown、缺失結果、壞 digest 或未結算的模型費用都不能解除停止。未知費用繼續占用原預留金額。人類說「沒有執行」不代替憑證。核對重播不推進第二次 round。

同一修訂的晚到模型工具結果會恢復原 run 的 calls，下一 round 只增加一次。領取時更換 epoch。舊 revision 的結果只留作證據，不恢復舊決策。已取消任務不重開。人工只讀工具沒有 provider call ID 時，已知同修訂結果作為有來源的資料加入 context；仍不作指令。模型再次提議同修訂已完成的同一讀取會被阻擋。

## 費用上界

兩家請求明確使用標準服務等級。固定短 context 的基本價格為每百萬 input US$0.10、output US$0.50。應用估算將所有 input（包含 cache read/creation）一律按最高 US$0.25 的 cache-write 費率計入，不假設折扣。這是保守估算，不是供應商帳單。

總 input usage 上界 65,536，輸出最多 1,024；估算上界 16,896 micro USD，小於每次預留的 20,000。送出前的訊息 context 上限 32 KiB，工具與系統提示固定。每日合計 US$1、每任務 US$0.25、8 次模型、16 次工具、15 分鐘的限制保留。費用與次數不因核對、修訂或重啟重置。

費率版本為 `luna-haiku-short-ceiling-2026-11-01`。來源：[OpenAI API pricing](https://developers.openai.com/api/docs/pricing)、[Claude pricing](https://platform.claude.com/docs/en/about-claude/pricing)。服務等級來源：[Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create)、[Claude service tiers](https://platform.claude.com/docs/en/api/service-tiers)。

## 真實故障驗證

2026-11-01，以真正 SwiftUI、Luna API、獨立 `pulse-executor` 和 `pulse-server` 執行：

1. A 只讀 Cargo.toml。測試 proxy 在 local 保存 finished 結果後，於 server 收到前斷線。
2. server 為 outcome_unknown；local journal 為 finished 一次。此時「核對 A」顯示仍未知，沒有新模型或派工。
3. 停止並重啟真正 server 程序，保持阻擋結果傳送。
4. 放行原 finished 憑證。local 重送結果，沒有重讀。server 保存已知結果，等待核對。
5. 桌面「核對 A」後仍是 blocked，原 run 的 round 1 ready，模型與讀取各仍一次。
6. 桌面「繼續 A」後，原 run 以新 epoch 使用原憑證回答 `pulse-core` 與 edition `2024`。最後為兩次 settled 模型呼叫、一次 local finished 讀取，任務仍待確認。

private fixture 為 `/private/tmp/pulse-replay-native-23445shs`，有 `unknown-before-restart.json`、`reviewed.json`、`continued.json`、server DB 與兩角色 journal。實際傳輸和核對邏輯使用 workflow `pulse-remote-5`。此故障實測完成於最後的快取費率上界調整前；新的標準服務參數另以兩家真實 API 驗證，各完成兩次呼叫與一次真實 repo 讀取。上界估算分別為 Luna 485、Haiku 956 micro USD。測試程序已停止。

正常測試另包含已知／未知／缺失憑證、未知費用、重複核對、取消、修訂、舊 epoch、偽造 digest、Tool 假批准、人工工具證據、拒絕重讀與超時模型結果。這些替身測試與上方原生程序證據分開計算。

## 重現故障位置

`crates/pulse-link/examples/replay_proxy.rs` 是測試工具，不放入 app，也不是產品 runtime。它只接受 loopback port，不記錄 headers、憑證或 payload。結果被阻擋時會中斷該連線；local 依正常 journal 重送。下列所有程序從 repo 根目錄啟動，使用同一個 private 目錄。

```sh
PULSE_TEST_DIR=$(mktemp -d)
sh scripts/build-macos-app.sh --debug
cargo build --locked -p pulse-link --example replay_proxy
```

分別啟動 server 與測試 proxy：

```sh
target/debug/pulse-server serve "$PULSE_TEST_DIR/server.db" 18744
target/debug/examples/replay_proxy 18744 18745 "$PULSE_TEST_DIR/allow-result"
```

另外產生 chat/local 配對檔，各用正常 CLI 連 `http://127.0.0.1:18745`，指定自己的 private data-dir、`--dev-loopback` 和 `--pair-code-file`。local 的 `--repo` 必須是獲准的 Pulse repository。配對與啟動步驟見 [Swift 桌面](swift-desktop.md)；API key 只在 server 私有環境，沒有交給 proxy 或桌面。

從桌面送上方 A 任務。看到 `allow-result.held` 後，local 已保存結果。可停止並用同一 DB 重開 server。之後建立 gate：

```sh
touch "$PULSE_TEST_DIR/allow-result"
```

等待原結果重送，再分別送「核對 A」與「繼續 A」。核對 SQLite 與 local journal 的操作數仍是一。這會使用真實 API；正常 CI 不啟動 proxy 或付費測試。測試完停止這些程序，保留 DB 供查核。
