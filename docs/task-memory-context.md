# 有來源的任務記憶讀取

Rust Core 現在提供 `Store::task_memory_context`。
它是可信本機 controller 的讀取入口，不是模型工具或新的 HTTP API。
Swift 仍只做介面。現有 provider 提示不會呼叫這個入口，模型記憶仍關閉。
這是 D06 的一個必要步驟，不代表 D06、D08 或 K15 已接受。

## 讀取規則

呼叫須提供目前的 run token、最大位元組數與可信處理時間。
任務須仍在同一修訂與執行世代，處於讀取規劃階段，且未取消或到期。
沒有明確採用來源的任務會返回空結果，不會取得其他任務或全域記憶。

Core 先取得原來源限制鎖，套用目前撤銷與到期，再開啟讀取交易。
它沿用原 Human 採用事件、完整摘要與父來源鏈的核對。
只查詢已採用的 1–8 個來源，不讀取無關正文。
每個來源須有相符的記憶修訂、來源 UUID、原寫入紀錄與到期時間。

Core 另以原記住或修正要求重算摘要，核對正文、標籤與來源時間。
舊來源保留原 UUID 拼法來核對原摘要；返回的來源識別仍使用標準拼法。
缺少原紀錄、正文被改寫、來源被修正或父採用證據失效時，整份讀取會拒絕。
來源到期或已保存撤銷時，必要清除仍會提交，不因這次讀取被拒絕而回滾。

## 結果與限制

`TaskMemoryContext` 包含原 token、Human 採用關聯、完整來源、核對時間及最近期限。
來源含標籤、正文、修訂、來源 UUID 與來源時間。
Debug 輸出沿用 `Memory` 的隱藏正文規則，不顯示標籤或正文。
這份資料只存在呼叫端記憶體，不另寫入事件、checkpoint 或新資料庫。

上限是完整 JSON 編碼後的位元組數，最多 16 KiB。
中文按 UTF-8 位元組計算，跳脫字元也占編碼空間。
超過上限時整份拒絕，不截斷正文，也不省略部分已採用來源。
這是本機資料大小限制，不是模型 token 數量保證。

讀取不建立工作，不預留費用，也不授權工具。
來源鎖不會跨越網路等待。
返回期限只是重查提示，這份資料不能當作持續有效的權限。
未來 provider 接入仍須在送出前與等待中呼叫 `validate_model_call`，並核對回覆提交。
已返回的字串無法被遠端撤回，不能沿用快照略過來源重查。

## 驗證與剩餘工作

`tests/task_memory_context.rs` 核對來源隔離、原正文證據、中文及編碼大小、修訂、
取消、期限、鎖忙碌、SQL 清除失敗、舊資料庫、父來源鏈及舊 UUID 拼法。
來源撤銷後，舊 provider 呼叫的核對仍失敗，原費用不退回。
這些測試使用隔離的合成資料，不呼叫 API。

```sh
cargo test --locked -p pulse-core --test task_memory_context
```

目前尚未將這份內容交給模型，也沒有新增對話採用命令或自動來源選取。
模型引用仍須完成原 adapter、副本清理、還原與兩家 provider 的完整驗收。
完整日常、原生介面、中文互動、效能及 8 小時運行要求仍保留。
