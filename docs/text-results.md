# Rust 文字成果匯出候選

這是 D09 的功能候選。完整 D09、D08、K15 與 Dot 目標仍未接受。
Swift 只顯示保存按鈕、開啟存檔視窗及送出原訊息識別與路徑。
Rust 負責成果、來源、下載、內容核對、寫檔及結果紀錄。
成果仍是分析草稿，不是任務完成或外部操作成功的證明。

## 使用流程

1. 在模型回覆下按「保存成果（Markdown）」。
2. 選擇新的 `.md` 檔名。Rust 不覆寫既有檔案。
3. 等待「已保存」、「未保存」或「狀態未確認」。

保存期間仍可使用對話框，也可按「取消保存」。
如果檔案已建立，取消不能假稱已撤回。
狀態未確認時，先檢查選定位置。程式不會自動重試寫檔。
成果不會自動開啟或執行。

## 原有資料與通訊

模型回覆與來源資料保存在同一筆原 run checkpoint。
來源與聊天文字在原交易保存，不增加另一套任務資料庫。
成果格式有獨立版本 1。remote workflow、模型、工具與費用規則不變。
舊 run 沒有可核對的成果紀錄時，保存會拒絕；不自動推定舊來源。

既有聊天訊息與傳輸摘要維持原格式。
人類按保存時，Rust 從私有 chat cache 取得原訊息及其摘要。
再以目前 chat 身分讀取 server 的成果識別資料與 Markdown。
兩次 HTTP 讀取都禁止重新導向；沒有離線猜測或任意網址入口。
Swift 不提供正文、任務範圍、修訂、批准或成果摘要。

server 核對原 Human 授權、有效決策、任務識別、修訂、原 run、聊天原文與內容摘要。
檔案輸入還須符合原固定副本與摘要。
資料缺失、被清除、被改動，或身分不是有效 chat 時，下載拒絕。
local executor 與模型不能使用此入口授權寫檔。

成果記錄任務、修訂、時間、模型、原 Human 來源及已保存的工具證據。
授權範圍與讀取證據分開記錄。沒有工具證據時，不宣稱已讀取外部資料。
來源描述不附加工具批准、操作 nonce 或 Pulse 存放的 API 憑證。
來源資料放在模型正文之前。正文中的不完整 Markdown 不會遮住前面的來源。
檔案最多 32 KiB。文字、來源與原 checkpoint 都有上限。

## 本機保存與重送

Rust 在寫檔前保存要求、身分指紋、目的位置與成果識別。
位置只留在私有 journal，不送到 server 或模型。
最多保留 128 筆匯出紀錄。容量不足時不建立新檔案。
同一要求識別只能配同一個訊息與位置。
重送已確認要求會回報原結果。重新開啟時，未確認要求會顯示為未知，不重寫。

Rust 只接受人類選定的絕對路徑與 Markdown 副檔名。
它拒絕私密目錄及不安全的路徑，並以目錄識別開啟父目錄。
完整內容先寫入私有暫存檔，再以不取代既有檔案的方式發布。
既有檔案、符號連結與硬連結都不會被覆寫。
最後同步失敗會回報未知，保留已發布的完整檔案。

## 驗收限制

模型記憶保持關閉。有記憶來源關聯的任務目前不能匯出。
不得在完成記憶來源與所有適用副本清除前，移除此限制。
匯出檔案仍在資料保留與刪除的驗收範圍內。
目前的匯出紀錄不是檔案所有權或清除成功的證明。
未知所有權、移動後副本、硬退出暫存檔、期限清除及正式還原仍須完成核對。
不能用保存成功宣稱 K15 通過，也不能自動刪除所有權未確認的檔案。

真正桌面存檔、實際模型成果與完整故障驗收仍待完成。
PDF、圖片模型輸入、其他成果格式及模型提出的受限寫入也仍待完成。
