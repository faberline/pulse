# 衍生聊天清除候選

這是 D06 的前置工作。模型仍不會收到記憶正文。
Swift 只顯示 Rust 回傳的狀態。來源核對、清除、重送與恢復都由 Rust 處理。
其他介面可以使用同一套 Rust 命令與狀態契約。

資料庫 schema 為 17。remote workflow 為 `pulse-remote-22`。
policy 為 `approved-effects-memory-fences-9`。不相容的舊 run 仍須重新核對。

## 保存與移除

Rust 在同一交易保存模型聊天與任務來源關聯。
關聯只含訊息、任務與修訂識別，不含記憶正文。
同一訊息不能更換或移除來源關聯。最多保存 10,000 筆關聯。

來源被忘記、修正、撤銷或到期時，Rust 清除對應回覆正文。
已確認和未確認的聊天傳輸副本都會清除。
清除通知保留原訊息識別、序號與摘要，不含正文，也不能啟動工具。
確認回覆遺失後，原確認仍有效，不會把清除通知當作新工作。

新聊天連線須先完成記憶同步，再宣告支援這種清除通知。
server 在每次連線重新核對能力。executor 不能宣告聊天能力。
未宣告支援的介面不會收到帶來源的模型回覆。
server 在送出前取得來源限制鎖，並限制傳送等待時間。

## 卡片與快照建立

操作卡片在保存前，先用 `Store::lease_task_memory_revision` 核對原任務修訂的來源。
任務後來換成不引用記憶的新修訂，也不能藉此略過舊卡片的來源限制。
來源鎖先於 SQL 交易取得。卡片與來源關聯仍在同一交易保存。
來源撤銷但 SQL 清除失敗時，不新增舊卡片；修復後先重做清除。

聊天快照先取得目前候選來源的短期限制鎖，再在同一 SQL 交易讀取訊息與交接通知。
每則帶來源訊息會再次核對原 Human 採用事件、任務修訂與父來源鏈。
尚未補上訊息關聯的舊操作卡片，也會從操作要求找到原來源，不能降為一般訊息繞過核對。
已標記清除的訊息只顯示固定清除提示，不讀回舊正文、批准或圖片。

來源證據失效時，快照略過相關內容，保留獨立的人類訊息。
來源鎖暫時忙碌或候選來源集合改變時，用既有連線計時器補查。
自動重查最多每秒一次，不建立背景工作或新佇列，也不呼叫模型。
一次只保留一個待重查標記；目前系統只允許一個有效 chat 角色。
重開後由正常連線與能力宣告重新建立快照。
資料庫交易失敗不確認通知交接。傳送前仍保留原有來源限制鎖與傳送期限。

這些測試使用合成來源及受控 helper。
真正 WebSocket 測試核對鎖釋放後無須新的人類輸入即可補送，且模型與預算紀錄均為零。
這不接受任意跨版本還原，也不開啟模型記憶。

## 地端副本

Rust chat 在保存回覆前，重新核對本機來源、修訂、到期時間與撤銷證據。
核對失敗時，只保存原訊息識別，不保存正文。
來源清除與正面回覆保存使用同一來源限制鎖。

忘記、離線修正、憑證失效與同步來源變更會移除相關聊天快取。
到期檢查也會移除快取。人的待送輸入獨立保存。
清除通知只會移除同序號或更早的帶來源快取，不會清除較新的獨立回覆。

重開時，Rust 先移除帶來源的聊天快取，再提供狀態給介面。
沒有目前撤銷證據的舊資料庫仍會拒絕開啟。
SQLite 清除提交後，必須完成 WAL 清除才會回覆確認。
若 WAL 正被讀取而不能清除，本次確認失敗。重送時仍會重做清除。

## 聊天圖片副本

Rust 的圖片下載現在只傳回有大小限制的記憶體內容。
它不先寫入檔案。
chat journal 在下載前、等待時與寫入前核對對話身分及原來源。
來源或身分失效時，會停止本機等待，不再保存晚到圖片。
這不表示遠端 HTTP handler 已停止。

server 另在每則訊息附上來源清單。
空清單表示該訊息獨立；舊訊息沒有此欄位時，沿用整份快照的來源。
訊息來源必須在快照已核對的來源範圍內。
兩個任務即使在同一份快照中，也不必共用圖片的來源。
這是可省略的欄位，沒有更改 wire major 或啟用模型記憶。

Rust 先保存檔案擁有紀錄，再寫入私人 PNG 內容。
紀錄包含任務、來源、圖片摘要及檔案和目錄的識別。
未完成寫入不提供預覽。
清除時先移除私人中繼資料，只保留沒有正文的檔案清除紀錄。
重開後會處理未完成的寫入與清除。

最後一個有效引用移除後，Rust 才刪除該 PNG。
獨立任務仍引用相同圖片時，檔案會保留。
清除會核對目錄與檔案識別、權限、硬連結及大小。
已完成的圖片另核對完整摘要。
中斷寫入依寫入前已保存的專用擁有紀錄核對，不提供預覽。
檔案遭替換或核對失敗時，保留檔案與待清除紀錄，回傳失敗。
刪除後須同步目錄，再清除紀錄及 SQLite WAL，才可確認清除。
不會猜測刪除沒有 journal 引用的舊檔。
舊引用只有在目前要求、原圖與預期路徑完全相符時，才會接入擁有紀錄。

server 的無正文清除通知可能早於來源同步到達。
若仍有其他帶來源的圖片，Rust 會先要求一次新的來源同步。
同步及檔案清除完成前，不確認該通知。
重送保留原訊息識別，也不清除較新的獨立圖片。
一次同步只核准一次確認嘗試。
確認遺失後，若仍有帶來源圖片，重送會再次同步，不能沿用舊同步結果證明後來的撤銷。
圖片仍限制 128 個檔案，引用紀錄另限制 1000 筆。

這些保證只涵蓋 Rust 已核對的 chat 快取。
Swift 已讀入的圖片、外部匯出、未知舊檔及正式還原仍須另外驗收。
