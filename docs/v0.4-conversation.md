## 對話方式

可直接輸入一般新需求。要交錯處理工作，可給任務一個短名稱：

```text
任務 A：只讀 README.md，說明專案用途。
任務 B：只讀 Cargo.toml，說明根套件名稱。
```

同一則訊息可有多行明確要求。server 會以同一 Human event 關聯這些任務。全部要求都必須明確；歧義或同時修改同一任務會先澄清，不只執行其中一部分。

```text
查詢 A 和 B
A 的狀態
修改 A：只讀 src/model.rs，說明 State 的用途。
補充 A：請標示來源檔案。
取消 B
繼續 A
```

「修改」會取代目前需求，請寫出完整的新需求。「補充」保留目前需求並加入要求。「繼續」只對安全的 blocked 任務有效，不能略過未知結果、期限、版本或預算。它也不能重送已預留的同一模型 round。未修改需求而再次繼續已保存的回答，不會使原 round 再次計費。

查詢與歧義澄清不建立任務、不呼叫模型。「取消它」不會猜測最近任務。未命名的任務可用完整 ID 指明。這是明確規則的判定，未使用模型猜測人類授權。它不支援所有自然語句；不確定時要求使用者明確說明。

## 保存與 context

名稱來自任務的初始 Human 決策，修改後仍保留。server 依保存的原始計畫重播訊息，不用新的任務修訂重新解讀同一 source ID。不同內容不可重用同一 source ID。

任務 context 只含目前 goal、最後一筆有效 Human 決策與其來源、scope、task/revision，以及同一修訂的必要工具證據。被取代的決策文字、其他任務或整段聊天記錄不會加入。舊 run 的 context 請求會被拒絕。Human、模型與工具的來源區隔不變。

## 2026-11-01 證據

正常 Rust 共 57 個測試，包含新增的多任務關聯、查詢／歧義不開任務、取消／修訂／繼續、訊息重播及有效 context 隔離。原有 140 個 hard-exit 子程序樣本仍通過。Swift 共 12 個測試，新增查詢回條在沒有新 task 時也會清空原草稿。fmt/clippy、macOS app 建置與簽章檢查通過。當前 head CI 另查，不以本機結果代替。

Luna 與 Haiku 各自以真正 SwiftUI、server、獨立 executor 完成以下情境：

1. local 離線。單一訊息建立 A 讀 README、B 讀 Cargo.toml。
2. A/B 各呼叫一次模型並等待裝置。查詢沒有增加 task、模型或工具呼叫。
3. 修改 A 改讀 src/model.rs。A 修訂為 2，B 維持修訂 1。
4. 「取消它」得到澄清，兩任務都未取消。
5. 接回 local，只執行 A 新的 src/model.rs 與 B Cargo.toml。沒有執行 A 舊的 README 提議。
6. A/B 各使用已知工具結果回答。A 共 3 次模型呼叫，B 共 2 次；各 1 次讀取。
7. 明確取消 B。A 仍為分析已保存，B 為 cancelled／修訂 2。
8. 關閉並重啟 server、app、executor。兩個角色從 Keychain 讀回。查詢仍顯示 A 待確認、B 已取消，沒有增加模型或讀取。

每家完整情境都是 5 次模型呼叫、2 次讀取。用量估算 Luna 458、Haiku 1,053 micro USD。這是本機估算，不是供應商帳單。Haiku 的證據收合／展開亦以原生控制項核對。
