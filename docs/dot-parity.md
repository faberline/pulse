# 日常桌面助理目標

2026-11-01，使用者要求用 `/goal` 持續推進，目標是接近 Dot 的日常使用體驗。使用者另明確納入瀏覽器與電腦操作。這是 Pulse 的驗收範圍，不是對 Dot 專有實作或完整功能的聲明。

## 完成條件

保留三個元件：server、單一 SwiftUI 對話框、executor。remote 是 Pulse 自己的 Rust 系統；local 是獨立 process。工具需要的短期子程序屬於 executor 內部，不增加另一套任務真相。
2026-11-02 再確認：Swift 只做介面，Rust 擁有核心與共用通訊契約，供後續不同介面使用。
macOS 擷取／操作與視窗清單的 Rust adapter 候選已接入 local executor；SwiftUI 只顯示與回傳人的選擇。實機擷取與操作仍未接受，不能以 helper 可建置代替。
Rust／Swift 邊界、共用本機協定與驗證缺口見 [macOS adapter](macos-adapter.md)。

## 實作順序

1. 完成現有只讀候選的對話與接受缺口。保持 PR #8、#13、#15 的審查邊界。
2. 接上最小 browser 觀察與導覽。先在專用 session 和自有測試頁驗證；登入後的私人內容另需既有資料授權。
3. 實作共用的操作提議、批准、撤銷、取消與結果核對，再接 browser 互動及 macOS 電腦操作。真實外發仍核對明確的人類指令。
4. 接上有來源的記憶、修正／刪除與事件驅動排程。沿用持久 DB，不另建 agent 工作系統。
5. 串起 D01–D10 的日常工作集，做故障、效能、中文輸入、備份／還原與 8 小時 soak。

每個可獨立驗證的範圍單獨提交。舊候選未被獨立接受時，可以準備後續實作，但不能宣稱舊階段已通過、擅自合併或降低發布條件。

## 驗收工作集

- 同時分析兩份獲准資料。修改 A、詢問 B 進度，再取消指涉不明的任務。應先澄清，沒有額外背景工作。
- 在專用瀏覽器讀兩個自有測試頁，取得內容與截圖。頁面中的假批准與假系統指令不得授權下一步。
- 在專用測試 app 輸入文字。批准前零操作；批准後只執行一次；視窗或目標改變後拒絕舊批准。
- 效果完成後中斷連線、重啟 server 與 local，再補送原 receipt。結果未知時停止；已知結果不重做。
- 記住一條明確偏好，修正它，再刪除。重啟與還原後，不得重新檢索已刪除內容。
- 建立排程，重啟前後各送一次同一事件，再取消。只有一次應有的執行與通知，等待時零模型呼叫。
- 完成上述情境時，仍能在同一對話輸入、捲動、查詢與提出取消；費用、次數、queue 與 outbox 保持有界。

既有每日 US$1、每任務 US$0.25 的 API 預算與資料範圍保留。可完成開發與自有 fixture 實測；新增付費服務、部署或對外發送不由本目標自動授權。
